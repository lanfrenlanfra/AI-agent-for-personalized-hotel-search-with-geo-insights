# Лупа — отели, у которых есть то, чего нет в описании

Хакатон Островка, трек «Найди отель, который подходит именно тебе, даже если в описании об этом ни слова».

Лупа собирает скрытые характеристики отелей (закат из окна, тишина по сторонам здания, вид на достопримечательность, пешее время до метро с переходами, белые ночи, ночные заведения рядом, стройка и т. д.) из открытых данных, **сверяет их между источниками** и честно показывает, насколько им можно верить: у каждого значения есть источник, цитата, дата свидетельства и уверенность. Устаревшее и спорное превращается в вопросы отельеру, свободные ответы которого разбираются в поля.

> Видео-демонстрация: **ВСТАВЬТЕ_ССЫЛКУ** *(запись экрана ≤ 5 минут — сценарий в разделе «Что показать на видео»)*

## Быстрый старт

Нужен только Docker (Compose v2.24+).

```bash
cp .env.example .env        # необязательно: без .env всё работает
docker compose up --build
```

Откройте http://localhost:8080. Проверка живости: `curl localhost:8080/health` → `{"status":"ok"}` (тот же адрес в healthcheck compose).

Образ собирается под `linux/amd64` (на Apple Silicon Docker запускает его через эмуляцию — в `docker-compose.yml` стоит `platform: linux/amd64`). Первый старт занимает меньше минуты: данные берутся из репозитория, ничего не скачивается.

### Реальные данные и демо-набор

* Если в `data/raw/ostrovok/` лежат собранные отели Островка — сервис работает на них.
* Если там пусто, при старте создаётся **синтетический демо-набор** (3 придуманных «Тестовых отеля» и придуманный квартал), и интерфейс прямо об этом предупреждает. Это не данные Островка — они нужны, чтобы показать механику без интернета.

Собрать настоящие данные (нужен интернет, ~10–20 минут на 30 отелей):

```bash
docker compose --profile collect run --rm collect     # Островок + тайлы OpenStreetMap → ./data
git add data && git commit -m "Данные Островка и OSM"
```

Без Docker: `pip install -r requirements.txt && python scripts/collect_ostrovok.py && python scripts/collect_osm.py`.

Если Островок отдаёт скрипту страницу антибота, есть запасной путь через ваш обычный браузер: откройте каталог на ostrovok.ru, вставьте в консоль `scripts/browser_export.js`, затем `python scripts/import_bundle.py lupa-bundle.json` и `python scripts/collect_osm.py`.

## Что умеет сервис

| Требование трека | Где это в Лупе |
|---|---|
| Агент собирает уникальные характеристики из открытых данных и от отельера | `app/collectors/` (карточка, отзывы, оценки, геоданные), диалог — `app/hotelier.py` |
| Хотя бы одна характеристика считается по геоданным | закат, вид на достопримечательности и воду, шум по 8 сторонам, пешие маршруты, ночные места, стройка, белые ночи — `app/geo/` |
| У каждого значения источник, уверенность, дата | таблица `observations`; кнопка «Откуда это?» показывает свидетельства, цитаты и метод |
| Конфликты выявляются и разрешаются | `app/reconcile.py`: статусы «подтверждено / вероятно / слабо / спорно / устарело», текст расхождения с обеими сторонами |
| Диалог с отельером, свободный ответ → поля | `app/hotelier.py` + кабинет `#/hotelier`; разбор правилами, с ключом LLM — умнее; ответ «имитируется» кнопкой |
| Расширяемость: новая характеристика по описанию | страница «Характеристики»: описание словами → черновик (LLM или ключевые слова) → применяется к отзывам всех отелей, подключается к поиску и вопросам; также запись в `app/features/registry.yaml` |
| Поиск на естественном языке | `app/search.py`: «тихий номер с видом на закат недалеко от моря» → критерии (чипы, их можно убрать), оценка и объяснение «почему подходит / не подходит» |
| Сравнение, кабинет отельера | `#/compare`, `#/hotelier` |
| Перепроверка устаревшего | `app/freshness.py`; кнопки «Перепроверить», демо «рядом построили дом → закат пропал» |
| Метрики качества и размеченная выборка | страница «Качество и свежесть», `app/metrics.py` |

Подробнее — [docs/architecture.md](docs/architecture.md) (как считается достоверность и геомодели) и [docs/research.md](docs/research.md) (как это делают Booking.com, Airbnb и что говорит наука).

## Маршруты и тестовые доступы

Интерфейс (hash-маршруты): `#/` поиск · `#/hotel/<id>` карточка · `#/compare?ids=a,b` сравнение · `#/features` характеристики · `#/quality` качество и свежесть · `#/hotelier` кабинет отельера.

**Кабинет отельера:** логин `hotelier`, пароль `hotelier123` (меняются в `.env`: `HOTELIER_LOGIN`, `HOTELIER_PASSWORD`). Остальное открыто без входа; ответы «за отельера» без входа помечаются как имитация и весят меньше.

API (JSON): `GET /health`, `/api/meta`, `/api/hotels`, `/api/hotels/{id}`, `/api/hotels/{id}/facts/{feature}?scope=`, `/api/hotels/{id}/horizon?az=&floor=&month=`, `/api/search?q=`, `/api/compare?ids=`, `/api/features` (+ `POST`, `POST /suggest`, `DELETE`), `/api/questions`, `POST /api/questions/{id}/answer|simulate`, `POST /api/hotelier/login|confirm`, `/api/freshness`, `POST /api/hotels/{id}/refresh`, `/api/metrics`, `/api/eval/candidates`, `POST /api/eval/labels`.

## Переменные окружения (`.env.example`)

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `APP_PORT` | `8080` | порт внутри контейнера (наружу всегда 8080:8080) |
| `LLM_BASE_URL`, `LLM_API_KEY`, `LLM_MODEL` | — | любой OpenAI-совместимый API; **необязательно**. Без ключа всё работает на правилах |
| `REGION_SLUG` | `russia/st._petersburg` | регион каталога Островка для сбора |
| `COLLECT_LIMIT`, `COLLECT_DELAY` | `60`, `1.5` | сколько отелей собирать и пауза между запросами (сек) |
| `HOTELIER_LOGIN`, `HOTELIER_PASSWORD` | `hotelier`, `hotelier123` | вход в кабинет |
| `REFRESH_ENABLED`, `REFRESH_INTERVAL_MIN`, `REFRESH_ONLINE` | `false`, `60`, `false` | фоновая перепроверка устаревшего (онлайн — с перекачкой) |

Секреты читаются только из окружения/`.env` (в git не попадает). Большие модели не нужны и не лежат в репозитории; при желании подключается внешний API.

## Как устроено доверие к данным

* Любое значение — **наблюдение**: характеристика, область (отель, «окна на запад», «во двор»…), значение, источник, уверенность, дата свидетельства, цитата, метод.
* Вес = уверенность × свежесть. Свежесть падает с возрастом относительно срока жизни характеристики (тишина — 180 дней, лифт — 365).
* Независимые источники усиливают друг друга; противоречие с заметным весом даёт «спорно» и показывается пользователю с датами и цитатами.
* Слово отельера весомо, но карта сверяется: если расчёт по OSM не допускает того, что он говорит, факт остаётся «спорно».
* Расчёт только по карте без независимого подтверждения не получает «подтверждено»; имитация отельера — тоже.

Пример из реальных данных: в карточке отеля стойка регистрации работает 10:00–22:00, а свежие отзывы говорят «стойка работает круглосуточно» — Лупа показывает оба свидетельства с датами и задаёт отельеру вопрос.

## Ограничения (честно)

* Docker-сборка и сетевой сбор с ostrovok.ru **не проверялись в среде разработки** (в ней не было интернета). Парсеры проверены на структуре реальных страниц и тестами на синтетических данных; если Островок отдаст антибот — запасной путь через браузер описан выше.
* Модель видимости 2.5D: высоты зданий берутся из OSM, где они заполнены не везде (иначе типовые 18 м); дальние препятствия (> ~1,4 км) и рельеф не учитываются. Поэтому геозначения без независимого подтверждения помечаются максимум «вероятно».
* Ночные заведения, парковки, стройки — по тегам OSM, которые обновляются с задержкой.
* Анализ отзывов — правила и словари; на новых характеристиках, описанных словами, качество ниже, чем на встроенных.
* Размеченной выборки нет: мы её не придумываем. Метрики точности появятся после разметки (вкладка «Качество и свежесть»).
* Фото пока показываются, но не анализируются; зрение по фото — следующий шаг (источник `photo_vision` в модели уже предусмотрен).

## Что показать на видео

1. Поиск «тихий номер с видом на закат недалеко от моря» — чипы критериев, оценка и «почему подходит».
2. Карточка отеля → «Откуда это?» у спорного факта (карточка против отзыва).
3. «Вид из окна»: этаж и месяц, силуэт и путь солнца.
4. «Рядом построили дом» → закат пропал → событие в истории → вопрос отельеру.
5. Кабинет отельера: свободный ответ → поля; добавление своей характеристики по описанию.
6. «Качество и свежесть».
